Collections grid — cover-mosaic tiles

Screen 2 · Collection detail

Inside a collection — the same grid the library uses

Opening a collection renders its documents through the same grid and toolbar as the full library — a collection is a view, not a different kind of screen. A back link returns to Collections; the header carries the name, a live document count, and a three-dot menu (Rename, Delete).

Screen 3 · Collection detail (list)

List view — and the per-document menu, in collection context

The list view is the same virtualized table as the library. Inside a collection, each document's three-dot menu gains Remove from collection (below Add to collection) — the only action that differs by context. Everything else — favorite, finished, rename, details, remove from library — is identical everywhere the menu appears.

Screen 4 · Add to collection

The collection picker — not a giant list of names

Reached from a document's menu. Each row carries a selected indicator (a filled check for collections the document is already in), the collection name, and its document count. An instant search filters as you type; when nothing matches, an inline Create "…" row makes the collection and adds the document in one step. Toggling a row adds or removes immediately (optimistic — the check flips before the server replies).

Screen 5 · Add to collection (create)

Create a collection from the search box

When the typed name matches no existing collection, the list collapses to a single Create "…" row. Selecting it runs the create mutation, then adds the document — server-validated (trimmed, whitespace-normalized, ≤ 80 chars, owner-scoped), optimistic in the UI.

Screen 7 · Name dialog

New collection / Rename — one dialog, two labels

A single name dialog serves both create and rename: focus-selects its input, trims and bounds the name (≤ 80 chars, matching the server's COLLECTION_NAME_MAX), and only submits when non-empty and changed. Names are re-validated and normalized server-side.

Screen 8 · Delete collection

Deleting a collection never touches the documents

A destructive confirm makes the consequence explicit: the collection is removed, the documents are not. Membership rows are cleaned up server-side; the files and every other collection stay exactly as they were.

Screen 11 · Favorites & Finished

Two saved views over the same library

Favorites and Finished are the library grid with a locked filter — Favorites a synced boolean toggled from the menu (Add / Remove from favorites), Finished derived from reading progress (Mark as finished / Mark as unread). No new list type: one library, filtered.

Screen 12 · Selection mode (grid)

Multi-select in the grid — Ctrl-click, Shift-range

Ctrl/Cmd-click toggles a tile; Shift-click extends a range from the last anchor. Selected tiles carry a primary ring and a tinted caption; hovering any other tile reveals a checkbox so the affordance is discoverable. Selection is an ephemeral view state — it survives the grid⇄list toggle and clears on Escape.

Screen 13 · Selection toolbar

Bulk actions — labels reflect the selection's state

With 14 documents chosen, the header becomes an action row. When all selected documents already share a state the verb flips: an all-favorited selection offers Remove favorite, an all-finished one offers Mark unread. Each action is one bounded bulk mutation (one rate-limit token), not fourteen round-trips.

Screen 14 · Bulk add to collection

An anchored popover — folder, name, count, live search

The toolbar's Add to collection opens a Radix Popover anchored under the button — not a modal. Each row shows a folder marker, the collection name and its document count; typing filters instantly, and an empty result offers an inline Create "…". The picker is action-oriented: clicking a row adds all selected documents at once and shows a transient Added, so several collections can be chosen before it closes.

Screen 15 · Selection mode (list)

The dense list gains a checkbox column

In list view selection adds a leading checkbox column; selected rows fill with the tint and a primary edge. The header checkbox selects or clears every loaded row, and shows a dash when only some are selected. TanStack row selection is keyed by the stable document id, so the same set carries straight over from the grid.

Screen 16 · Single-doc picker + offline

One picker vocabulary — and a quiet sync affordance

The single-document dialog reads the same as the bulk popover: a folder marker and document count on every row, with a filled check for the collections this document is already in (true membership state). When edits are made offline, a Changes will sync chip appears in the header — the write lands in the local mirror instantly and drains to Convex on reconnect, so organizing never waits on the network.
