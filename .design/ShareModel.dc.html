Identity, membership, access
Three separate things. Collapsing them into one "shared PDF" row is what makes a person leaving a group into a hundred rows somebody has to remember to delete.
How a recipient is allowed in
The document
One row, one owner, one object in R2. Sharing never copies it and never changes who owns it.
A grant
documentShares — who, what role, can they download, can they share it on, and when it stops.
Resolved on every read
Owner first, then a direct grant, then a group the caller is in. Nothing is cached into a session.
What removing access reaches
Immediately
Opening it again.
Downloading it again.
Their notes syncing to you.
Joining the presence room.
Never
A copy already downloaded to their phone. It is a file on a disk you do not own, and no server can reach it.
This is why downloading is off by default and asked for per share.
Unchanged
Your own document, your own file, your own notes. Removing access is a change to a grant and nothing else.
The file still moves the same way
A recipient downloads through a signed R2 URL that lives for five minutes and is minted only after the grant is checked — the same mutation the owner's own devices use, with a different check in front of it. There is no permanent link, and no URL that outlives the permission it was issued under.
And it still reads offline
Once accepted and downloaded, a shared document is a row in this phone's database and a file beside it, like every other document. Opening it touches no network. That is the whole point of putting sharing above the local-first library rather than beside it.
